# ferry（Gemini / Antigravity 侧）

跨软件消息桥。这条通道有两个硬限制，都来自 Antigravity 本身：

1. **只能接收发往界面里已经打开的对话的消息**，没法后台注入。
2. **同时开多个对话窗口时，无法保证消息落到你指定的那个。** CDP 只能向当前渲染的页面注入，哪个在前台由界面决定。工具不会因此拒绝投递，但会打印警告；稳妥做法是同时只开一个。

## 先看现状

```powershell
ferry list
ferry queue
ferry doctor
```

`doctor` 会打印当前打开的是哪个对话，以及是否开了多个。开着多个时先关到只剩一个。

## 发消息（不受限制，后台也能发）

```powershell
$body = @'
正文
'@
$summary = '说清要对方做什么，300 字内'
$b64 = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($body))
$b64 | ferry send --to dsh-work --from "Gemini" --summary $summary --expect report
```

## 收消息

```powershell
ferry receive --to gemini-work
ferry flush gemini-work
```

`receive` 会把正文完整打出来，然后从信箱移除并归档，最后给出点名回执。把回执用 `send` 发回对方，并带上你自己的凭证。

## 收到消息：两次回复

完整规约见 `skills/_shared/two-replies.md`，四条要点：

**第一次回复（必做，立即）** 只回「收到」，然后开始处理。这句话只表示已收到并开始读取，不代表工作已完成。不夹带正文，不等处理完再一起回。

**第二次回复（按消息性质分四类）**

| 情况 | 怎么回 |
|---|---|
| A 纯通知、无异议 | 不回，结束回合 |
| B 有异议或需澄清 | 只回异议点，带实测依据 |
| C 已安排的任务做完 | 回做了什么、实测数字、剩余风险、待裁决项 |
| D 已安排的任务没做成 | 回失败原因、卡点、试过的路径、建议 |

判断标准：这条回复发出去，对方能读到它原本不知道的东西吗？答案是「没有，只是知道我收到了」就不该发。

**低耗执行**：收件、解析、回 ACK 属于格式搬运，不展开深度思考，也不顺手分析消息的学术或工程含义。


## 硬规则

- 给别的 agy 对话发消息前，先确认界面打开的是目标那个。发错对话是真实事故，曾经把仿真讨论灌进了留学文书对话。
- 被列入 `blocked` 的对话一律不碰。
- 长正文不要一次性粘贴，工具内部已经按行插入；自己手动粘贴时注意别在第一个换行处触发发送。
- `humanSleeping` 只读，不要改。

## 故障

| 现象 | 处理 |
|---|---|
| 目标未打开，已转信箱 | 界面切到该对话，再 `flush <别名>` |
| 提示同时打开了多个对话 | 只是警告。确认前台那个是不是目标；不是就切过去，或关掉多余的窗口 |
| 注入不完整 | 工具会中止而不是发半截。检查窗口是否被切走 |
| 输入框已有草稿 | 工具拒绝覆盖。先手动清空或把草稿发出去 |
| 未确认接受 | transcript 里没出现凭证。先 `queue` 看，不要盲目重发 |
